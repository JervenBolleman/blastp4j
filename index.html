blastp4j against BLAST+

Every run of the architecture comparison workflow. The ratios are blastp4j over BLAST+ in the full search, measured in the same job. Hosted runners are virtual machines on varying CPUs, so compare runs on the same CPU model.

Over the runs

Six lines: blastp4j, almostblastp and fastblastp, on each architecture, over the BLAST+ task each one must match (blastp for the first two, blastp -task blastp-fast for fastblastp, which also runs more queries). A point is one job: the median of its rounds' ratios, and the bar is the lowest and the highest of them. A diamond instead of a circle marks a job on AMD Zen 5, the one runner CPU that bin/jvm.options gives 512-bit vectors; the other x86-64 CPUs keep 256, so those points measure code built for a different vector width. Numerator and denominator come from the same round of the same job, which is what makes the runs on different runner CPUs comparable; what scatter is left between neighbouring points is the runners themselves. A dotted line marks a change of database and queries, across which the ratios are of different searches. Click a point for that run's report; the table below has every run, the Mac workflow's among them, which this chart leaves out.

Per commit

Each point is one round of the full search: blastp4j's wall time over BLAST+'s, or over the reference commit's, in the same round of the same job, which keeps the different runner CPUs comparable. All rounds of all runs of a commit, newest commit first; open a commit to draw its plots.
